The lack of state problem in Bitcoin is that Bitcoin nodes do not keep a persistent state between blocks in the blockchain. The nodes process each block independently. They do not consider the state of the previous block.

**Points**

1. **No persistent state:** Bitcoin nodes do not keep a persistent state between blocks. They process each block independently. The state of the blockchain resets after each block.
2. **No memory of previous transactions:** Without a persistent state, nodes have no memory of previous transactions. They process each transaction independently. They do not consider the history of the addresses.
3. **No accounts or balances:** Bitcoin does not keep accounts or balances for individual users. It uses an unspent transaction output (UTXO) model. Each UTXO is a specific amount of bitcoin that a transaction can spend.
4. **No state transitions:** A traditional stateful system uses state transitions to move from one state to another. Bitcoin has no state transitions, because it processes each block independently.
5. **Implications:** The lack of state makes it difficult to implement features that need a persistent state, such as smart contracts. It also makes it difficult to implement certain types of fraud proofs. There is no way to refer to the state of a previous block.

**Table: stateful and stateless systems**

| Feature | Stateful System | Bitcoin (Stateless System) |
| --- | --- | --- |
| Persistent state | Maintained between transactions | Not maintained |
| Memory of previous transactions | Yes | No |
| Accounts or balances | Maintained | Not maintained |
| State transitions | Used to move from one state to another | Not used |
