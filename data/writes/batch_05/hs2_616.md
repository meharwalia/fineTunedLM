Multiplayer games use four techniques to give each player the same game state for each frame. The game does not save every frame beforehand. The technique depends on the game design, the network infrastructure, and the available resources.

1. **Server-authoritative.** The game server generates the game state for each frame. It sends the relevant information to each player. This technique needs a fast and reliable network connection between the server and the players. The players must receive the game state for each frame.
2. **Client-authoritative.** The client of each player generates the game state for each frame from the inputs of the player. The client sends the relevant information to the server. The server verifies the game state. Then it sends the game state to the other players. This technique needs a fast and reliable network connection between the players and the server. The players must send the game state to the server for each frame.
3. **Hybrid.** This technique combines the server-authoritative and client-authoritative techniques. The server generates the game state. The client generates the game state for each frame from the inputs of the player. The client sends the game state to the server for verification. The server sends the verified game state to the other players. This technique needs a fast and reliable network connection between the server and the players. The players must send the game state to the server for each frame.
4. **Pre-computed.** The game generates the game state once. It saves the game state on the server or the client for each frame. The server or client retrieves the game state for each player from the position and orientation of the player in the game world. This technique needs a fast and reliable network connection between the server and the players. The players must receive the game state from the server for each frame.
